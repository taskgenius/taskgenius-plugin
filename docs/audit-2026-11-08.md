# Task Genius 旧布局版本审计与修复

## 结论

这些问题主要来自多套视图状态、异步初始化、缓存失效和生命周期管理没有统一衔接。旧版本持续叠加新组件增加了维护成本，但“代码较旧”本身不能解释每个问题，也不能据此认定整个系统无法使用。

本轮保留原有导航入口、任务状态顺序、习惯数据格式、页面结构和主设置布局。修复集中在数据与界面的同步、旧实例退出和已有关闭按钮的事件处理；不进行界面改版，不迁移用户笔记，不改写任务文件。

## 用户报告的八项问题

| 项目 | 代码问题与修复 | 验证 |
| --- | --- | --- |
| 列表、树状连续切换卡顿 | 内容区与顶部导航各自维护模式；刷新还重建未变化的标签。统一切换入口，明确下发当前模式，保留未变化的标签 DOM，取消同步渲染结束后的额外延迟锁。 | 连续切换、标签节点稳定性、强制刷新后连续更新 |
| 首次进入偶发空白 | 首次查询先于缓存事件订阅；初始化期间的变更被丢弃；旧查询可能覆盖新结果；隐藏待刷新时拒收新数据。订阅先于查询，保留初始化期间的待刷新状态，按请求顺序接收最新结果，重新可见后自动绘制。可见性判断使用元素所属文档。 | 隐藏后更新、初始化中更新、延迟查询乱序、卸载后查询完成 |
| 年份页不能向下滚动 | 实际承载年份网格的内层 `.tg-view-container` 设置了 `overflow:hidden`。保持十二月网格，修正该内层滚动口及父级 flex 最小高度。 | 真实 Obsidian 离屏测试：12 个月，滚动内容高度大于可视高度，`overflow-y:auto`，滚动位置可改变 |
| 日历翻页标题不更新 | 日历本体和外层标题使用两套日期；原来没有连接日期变化回调。连接内置、自定义日历的 `onDateChange` 并更新已有标题节点。 | 实际日历引擎的月、周、日、年往返导航 |
| 删除独立 Habits 提示 | 删除页面和设置中的提示调用，保留双插件共用记录时避免重复后台写入的处理。 | 源码检查、原习惯兼容测试 |
| 修改视图设置后页面不更新 | 部分设置仅保存配置；已缓存的组件没有比较配置变化。保存时对 UI 配置做值快照并通知视图，刷新导航和配置；日历配置更新保留当前日期，其他失效组件重新创建。工作区导航状态保存不触发全局配置刷新。 | 配置原地修改、导航状态保存、配置缓存失效、日期保留 |
| 创建习惯叉号无效 | 实机确认是新版 `.modal-header-button`，不是图标清除按钮，且没有视觉遮挡。为新旧原生关闭控件补充限定在本弹窗内的 pointer-up / 捕获阶段关闭处理，关闭时移除处理器。未把未经捕获的错误猜测写成已证实根因。 | 两种控件名称、文档 click 被拦截时关闭、处理器清理；实际使用仍需用户确认 |
| 项目快捷入口与项目总览冲突 | 总览主动禁用了侧栏项目入口；侧栏重绘遗留旧列表，旧异步结果可能回写；带引号的项目名会破坏 CSS 选择器。恢复入口可用性，同步当前项目，清理旧列表并拒绝其迟到结果，使用属性值比较定位项目。 | 总览/具体项目状态、特殊字符名称、旧列表卸载后异步结果 |

## 审计覆盖与方法

全仓静态遍历覆盖 `src`、`packages/calendar/src`、构建脚本及 GitHub 工作流；文件和行数清单在 `audit-2026-11-08-inventory.json`，可用 `node scripts/audit-source-map.cjs` 重建。清单包含测试文件，静态信号不等于已确认缺陷，也不代表每一行都已逐行人工证明正确。

重点逐段检查的运行路径：

| 模块 | 检查内容 |
| --- | --- |
| Fluent 页面及组件管理器 | 初始化、模式切换、空/加载状态、重复绘制、缓存组件 |
| 列表、树、分组 | 数据签名、隐藏视图恢复、渲染锁、分组子组件清理、排序开销 |
| 侧栏与项目 | 总览/快捷入口、重绘、异步请求、项目标识与 DOM 定位 |
| 主设置与视图设置 | 直接保存/完整应用的不同路径、配置快照、通知、工作区状态隔离 |
| 日历及日历库 | 内置/自定义视图、日期回调、年份布局、事件和容器生命周期 |
| Dataflow | 缓存就绪、增量更新、设置重建、项目缓存失效、持久化与关闭 |
| WriteAPI 与文件任务 | 文件接口、读改写流程、批量操作与行定位；不在真实笔记执行破坏测试 |
| 习惯、导入与 Reminder | 原数据兼容、重复导入、文件冲突、同步归属、弹窗和关闭 |
| AI 与导出 | 显式请求入口、统计摘要范围、缓存身份、PDF 生成 |
| MCP、桌面与配置迁移 | 监听地址/认证入口、令牌生成、迁移触发、旧版本兼容声明 |

## 同时修正的其他问题

- 分组子渲染器递归释放，避免刷新后旧子组件仍监听事件。
- 项目列表初次加载后重复绘制；现在保留一次绘制。
- 相同顶部导航实例重新绑定时不再关闭正在查看的计时统计。
- 默认排序复用一次 `Intl.Collator`，比较规则和排序结果保持原样。
- 独立习惯页不再被“任务总数为零”的空任务界面遮盖。
- AI 总结缓存纳入接口地址，切换同名模型的服务后不会复用另一接口的结果。
- MCP 新令牌改用安全随机字节并保持原来的 32 位字母数字格式；已有令牌不变。

## 尚需独立处理的遗留风险

1. **原测试基线仍不干净。** 原有 Jest 在本机是 1,349 项通过、147 项失败。包含旧接口 mock、缺失模块路径和既有行为断言失败，不能把这些失败一概视为无害。本轮对失败测试的文件名和完整测试名逐项比对，没有新增失败，不删除或跳过原测试。
2. **文件写入的并发风险。** `WriteAPI` 的多条路径使用“读取内容 → 修改字符串 → `vault.modify`”。未见统一覆盖所有写入入口的同文件串行控制；两个不同操作同时作用于同一笔记时值得专门做并发一致性测试。本轮不贸然重写任务写入引擎。
3. **版本兼容声明落后于实际 API。** manifest 仍声明最低 Obsidian `0.15.2`，而引用的 `AbstractInputSuggest` 在类型说明中标注自 `1.4.10` 提供。这是历史兼容承诺问题，不能据 manifest 推断老客户端都能运行。未因此强制用户升级或改变当前安装方式。
4. **部分日历任务完成状态仍硬编码默认符号。** 当前使用默认完成/未开始符号时不受影响；若换成非默认符号，需要独立覆盖日历写入与自定义状态的组合测试。
5. **全局 DOM 引用与延迟回调仍分布于其他旧模块。** 本轮修复报告问题涉及的可见性、查询和组件销毁路径；其他多窗口、移动端和第三方集成场景不能仅凭静态扫描宣称全部验证完毕。

这些条目区分“已确认并修复的问题”和“有源码依据、尚需专门验证的风险”。本报告不是零缺陷或所有平台完全一致的保证。

## 验证与交付

- `pnpm test:ui`：页面/导航、日期、设置、项目、关闭按钮、令牌生成回归。
- `pnpm test:habits`：原习惯交互、统计、导入、提醒、双插件共存、PDF 及模拟 AI 接口。
- `pnpm check:i18n`：保留原有 1,800 个设置词条，检查习惯模块中英文占位符。
- `pnpm build`：TypeScript 和生产 JavaScript/CSS 打包。
- 原有 Jest 全量运行，与未修改版本的失败名单比对。
- 实机离屏年份滚动验证没有切换用户当前页面、没有输入鼠标键盘动作、没有修改笔记。

实际安装和用户确认结果另存于本地安装记录，测试报告不会把未进行的实机交互写成已通过。
